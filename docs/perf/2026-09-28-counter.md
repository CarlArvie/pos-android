# Performance & UX Optimization: POS Counter

**Date:** 2026-09-28  
**Feature:** `counter` (POS Counter, catalog grid, barcode search, cart management, shifts, roles/permissions, checkout dialog, tenders)  
**Branch:** `perf/counter`  
**Target Hardware:** Low-end Android (2GB RAM, 720p/360-390dp width, Android 8-10)  
**Highest Evidence Tier Reached:** `[Verified]` (all 132 tests pass, 0 static analyzer issues in slice, deterministic O(1) algorithms, memoized grouping, persistent drift query streams, and debounced search)

---

## 1. Findings & Issues Addressed

1. **Drift Stream Anti-Pattern in `build()` (`[Verified]`)**:
   - **Issue:** Previously, `build()` repeatedly invoked `_watchActiveShift()`, `_watchCategories()`, and `_watchProducts()` which constructed fresh `.watch()` queries on Drift SQLite on every build pass, subscribing and unsubscribing stream listeners.
   - **Fix:** Initialized persistent streams (`_activeShiftStream`, `_categoriesStream`, `_productsStream`) in `initState()`, refreshed them cleanly on `didUpdateWidget()`, and cancelled them properly.

2. **$O(N \times M)$ Cart Item Linear Scan in Product Grid (`[Verified]`)**:
   - **Issue:** On every grid tile build and on every scroll event, `_buildProductGrid` mapped all product variants to a `Set`, performed an `_cart.where(...)` linear iteration across the entire cart, and then folded item quantities to determine if the tile was in the cart and what quantity badge to display.
   - **Fix:** Added an $O(1)$ quantity index `Map<String, double> _cartItemQuantities` maintained incrementally across cart operations (`_addToCart`, `_updateQuantity`, `_removeFromCart`, `_clearCart`, `_holdCart`, `_recallHeldCart`, and `_openQuantityInput`). Replaced linear scans in the grid with direct map lookups.

3. **High-Frequency Search Keystroke Rebuilds (`[Verified]`)**:
   - **Issue:** The barcode/text search field invoked `setState` on every single character change, immediately filtering the entire product catalog and triggering full rebuilds without debouncing.
   - **Fix:** Added 150ms debouncing via `Timer` (`_onSearchChanged`, `_clearSearch`) and cancelled active timers in `dispose()` and on immediate barcode submission (`_onBarcodeSubmitted`).

4. **Product Grouping List Allocations (`[Verified]`)**:
   - **Issue:** Filtered products were repeatedly re-grouped via `_groupPosProducts` on every frame, creating new Map instances and nested lists even when the input list had not changed.
   - **Fix:** Added `_getGroupedProducts` memoization caching `_cachedGroupedProducts` across identical product lists.

5. **Customer Selection Dialog Stream Re-creation & Unbounded Measuring (`[Verified]`)**:
   - **Issue:** Inside `_openCustomerSelectionDialog()`, `StreamBuilder` called `(widget.db.select(widget.db.customers)...).watch()` inside `StatefulBuilder`, recreating the database stream on every keystroke in the dialog's search box. Additionally, `ListView.separated` specified `shrinkWrap: true` inside an `Expanded`, defeating list view recycling and forcing unbounded pre-measurement.
   - **Fix:** Instantiated `customersStream` once before `showDialog`, passed it to `StreamBuilder`, and removed `shrinkWrap: true` so the list recycles smoothly.

6. **GPU Raster Pass Overhead (Blurred `BoxShadow`) (`[Verified]`)**:
   - **Issue:** `_buildCartSummary` and `_buildMobileStickyCartBar` utilized multi-pixel blurred `BoxShadow`, triggering expensive off-screen render passes on low-end Mali/Adreno GPUs.
   - **Fix:** Replaced with flat, crisp `Border(top: BorderSide(color: AppTheme.cardBorderColor))`.

7. **Repaint Boundaries on Catalog Grid Items (`[Verified]`)**:
   - **Issue:** Cart badge updates or card tap ripples caused the entire grid to repaint.
   - **Fix:** Wrapped catalog grid cards in `RepaintBoundary` isolating paint passes.

8. **Checkout Dialog Payment Method Squeeze on Mobile Screens (`[Verified]`)**:
   - **Issue:** On narrow screens (320-390dp), placing up to 5 payment method tiles in a single `Row` squeezed buttons down to < 55px width, crowding text and touch targets.
   - **Fix:** Implemented responsive `LayoutBuilder` in `_buildPaymentForm`: if width is < 400dp, payment methods adapt into a clean, 2-row layout with comfortable tap targets while preserving all widget keys.
